# Figma 页面拼装器

根据已有的产品（网页 demo、iOS 应用、Android 应用）加上产品需求文档（PRD），在指定的 Figma 文件里把完整的页面流程拼出来。

> 这个工具是「Figma 组件创建器」的下一步。要先有一份做好的组件库才能用它。

## 主要会做的事

### 启动准备
- 读取项目里已有的设计约束和历史记录
- 检查现成的组件库是否够用
- 如果发现没有组件库，停下来建议先去建组件库

### 摸清产品需求
- 识别需求文档是什么形式
- 把需求文档转成结构化的内容
- 列出需求涉及的所有功能模块

### 校对源头和需求
- 对照已有产品和需求文档
- 找出两者不一致的地方
- 让你裁决以谁为准

### 检查组件够不够用
- 列出每个页面需要用到哪些组件
- 跟现有组件库一项一项比对
- 找出缺的、不够用的、需要扩展的
- 把缺口告诉你，等你决定怎么办（去补 / 用现成的代替 / 你给方案）

### 定下设备目标
- 询问目标端是手机、平板还是网页
- 多端就为每端各准备一份

### 画交互流程图（两步走）
- 先画文字版的流程图给你看（方便快速改）
- 等你确认结构对了，才在 Figma 里真的画
- 流程图会涵盖正常路径、异常路径、各种弹层

### 整理页面清单
- 列出每个页面的所有状态
- 列出每个状态用到哪些组件、哪些规则
- 标明每个页面对应需求文档的哪个章节
- 等你审阅

### 得到你明确许可后开始拼页面
- 按流程一个个拼，不会跨流程混批
- 每批不会一次扔太多页面
- 严格使用现有组件，不会自己画
- 每批拼完会自己比对源头
- 视觉不接近源头不交付

### 每批拼完暂停等你
- 让你去 Figma 里验收
- 你可以让它继续、改这批、重做这批、先停下

### 收尾
- 把这次做了什么记录到项目里
- 把替代方案的记录留下，方便以后补
- 给你一份总结报告

## 它绝对不会做的事

- 未经你同意就开始动手
- 没有现成组件就自己画一个
- 静悄悄用现成组件替代缺口，不告诉你
- 一次性扔给你一大堆页面
- 跳过你的验收
- 把页面拆离组件（拆离之后就跟组件库断了同步关系）
- 用凭印象拍脑袋的数值

## 怎么激活它

跟它说类似的话：
- 按 PRD 在 Figma 里拼页面
- 把这个流程在 Figma 出页面
- 基于 demo 加 PRD 出一套页面
- 做一份完整的交互流程加页面

## 前置依赖

使用前需要先有一份组件库（用「Figma 组件创建器」做好的）。如果没有，这个工具会告诉你先去做。
